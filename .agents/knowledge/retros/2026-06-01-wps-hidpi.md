# WPS Office HiDPI 修复 — 完整复盘

## 背景

WPS Office 在 2560x1600 高 DPI 笔记本屏幕 + niri Wayland 下 UI 元素偏小喵~

## 最终方案（用户确认）

**只放大演讲备注字体**，不做全局缩放。

用户手动修改 `Office.conf`：
```
SlideShowPresenterNotesFontSize=20 → 30 (1.5x)
```

此设置是独立的，只影响演讲者模式下的备注字体大小，不影响 UI 缩放。

## 失败的方案（全部回退）

### 方案 1: QT_SCALE_FACTOR（全局缩放）❌
- 设置 `QT_SCALE_FACTOR=1.75` → 窗口太大，只能看到左上角
- 降低到 `1.25` → 还是太大，右边看不到
- 降到 `1.1` → UI 略大但文档注释变小看不见
- **结论**: Wayland 下 QT_SCALE_FACTOR 影响窗口几何，高倍率不可行

### 方案 2: common\dpi（WPS 原生 DPI）❌
- 设置 `common\dpi=144` → 主页面 OK，但文档内容仍然偏小
- **结论**: WPS 内部有多个独立 DPI 系统，主 UI 和文档渲染走不同管道

### 方案 3: ZoomOfFirstView（文档缩放）❌
- 设置 `ZoomOfFirstView=200` → 新建文档 zoom 200%
- 但已打开的文档用自身保存的 zoom 值
- **结论**: 只影响新文档默认值，不覆盖已打开文档

## 踩坑记录

| # | 坑 | 教训 |
|---|-----|------|
| 1 | QT_SCALE_FACTOR 撑爆窗口 | Wayland 下窗口几何也被缩放，高倍率不可行 |
| 2 | 不同倍率都不满意 | 1.0~2.0 之间没有合适的值 |
| 3 | common\dpi 只对主 UI 有效 | 文档渲染走独立管道 |
| 4 | ZoomOfFirstView 只影响新文档 | 已打开文档用自身 zoom |
| 5 | xdg.desktopEntries 不生成文件 | 用 home.file 直接写更可靠 |
| 6 | writeShellScriptBin 冲突 | 与同名包在 home.packages 中冲突 |
| 7 | symlinkJoin meta.priority 不生效 | home-manager 不尊重优先级 |
| 8 | 用户只需局部放大 | 先问清楚需求，不要假设全局缩放 |

## 关键教训

1. **先问再做**: 不要假设用户需要全局缩放，先确认具体需求
2. **增量测试**: 每次改一个设置就让用户测试，不要一次改太多
3. **Wayland 限制**: QT_SCALE_FACTOR 在 Wayland 下会影响窗口几何，高倍率不可行
4. **WPS 多管道**: 主 UI / 文档渲染 / 演讲备注是三个独立系统
5. **回退方案**: 用户说"不行"时要能快速还原所有改动
6. **手动修改更简单**: 对于 WPS 内部设置，直接改 Office.conf 比 Nix 配置更直接
