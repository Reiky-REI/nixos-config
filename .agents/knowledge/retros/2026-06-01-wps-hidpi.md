# WPS Office HiDPI 修复 — 完整复盘

## 背景

WPS Office 在 2560x1600 高 DPI 笔记本屏幕 + niri Wayland 下，UI 元素、备注字体、演讲模式、文档内容都太小喵~

## 问题分层

WPS 的缩放涉及 **三个独立系统**：

| 系统 | 控制什么 | 配置方式 |
|------|---------|---------|
| **Qt UI 缩放** | 菜单、工具栏、对话框 | `QT_SCALE_FACTOR` 环境变量 |
| **文档内容缩放** | 打开文档时的默认 zoom | `ZoomOfFirstView` 等 Office.conf 设置 |
| **演讲备注字体** | 备注区文字大小 | `SlideShowPresenterNotesFontSize` |

三者互不影响，必须分别设置。

## 踩坑记录

### 坑 1: useSystemDpi=1 在 Wayland 下无效
- `Office.conf` 中 `common\useSystemDpi=1` 对 WPS 的嵌入式 Qt 无效
- WPS 使用自定义 Qt 构建，不读取系统 DPI
- **教训**: Wayland 下 Qt 应用的 DPI 检测不可靠，必须显式设置

### 坑 2: writeShellScriptBin 与同名包冲突
- `pkgs.writeShellScriptBin "wps"` 创建 `bin/wps`
- `wpsoffice-cn` 也提供 `bin/wps`
- 两者都在 `home.packages` 中 → `buildEnv` 报 "conflicting subpath" 错误
- **教训**: 不要在 `home.packages` 中同时放原包和同名包装

### 坑 3: symlinkJoin 的 meta.priority 不生效
- 尝试用 `symlinkJoin` 合并两个包，设置 `meta.priority = 1`
- home-manager 的 `buildEnv` 不尊重这个优先级
- 原始 WPS 脚本仍然覆盖包装脚本
- **教训**: `meta.priority` 在 home-manager 中不可靠

### 坑 4: xdg.desktopEntries 不生成本地文件
- `xdg.desktopEntries` 配置正确但 `~/.local/share/applications/` 里没有文件
- niri 启动器用的是系统 nix store 中的原始桌面文件
- **教训**: `xdg.desktopEntries` 不可靠，用 `home.file` 直接写更稳

### 坑 5: niri 启动器不继承用户 PATH
- 即使 `~/.local/bin/` 在用户 PATH 中，niri 桌面启动器执行 `Exec=wps %F` 时可能不走用户 PATH
- 导致 `~/.local/bin/wps` 包装脚本不被使用
- **教训**: 桌面启动器的 PATH 环境不可预测，必须在 Exec 行直接注入 env

### 坑 6: 文档缩放与 UI 缩放是独立系统
- `QT_SCALE_FACTOR` 只放大 UI（菜单/工具栏）
- 文档内容的缩放由 `ZoomOfFirstView` 等独立设置控制
- 演讲备注字体由 `SlideShowPresenterNotesFontSize` 独立控制
- **教训**: WPS 内部有多个独立的缩放/DPI 系统，不能只靠 Qt 环境变量

## 最终方案

**文件**: `home/Reiky-REI/apps/office.nix`

### 三层设置

| 层级 | 配置 | 覆盖场景 |
|------|------|---------|
| **QT 缩放** | `~/.local/bin/wps` 包装脚本 + 桌面文件 `Exec=env QT_SCALE_FACTOR=1.75` | 终端 + 桌面启动器 |
| **文档缩放** | `ZoomOfFirstView=175` + 相关设置 | 打开文档时的默认 zoom |
| **演讲备注** | `SlideShowPresenterNotesFontSize=30` | 演讲者模式备注字体 |

### 包装脚本链路

```
终端 wps → ~/.local/bin/wps (QT_SCALE_FACTOR=1.75) → /nix/store/.../bin/wps (原始 wrapper) → WPS 二进制
桌面启动器 → ~/.local/share/applications/wps-office-wps.desktop → env QT_SCALE_FACTOR=1.75 → wps → WPS 二进制
```

### 为什么用 home.file 而不是其他方案

| 方案 | 结果 | 原因 |
|------|------|------|
| `home.packages` + `writeShellScriptBin` | ❌ 冲突 | 与 `wpsoffice-cn` 都提供 `bin/wps` |
| `symlinkJoin` + `meta.priority` | ❌ 不生效 | home-manager buildEnv 不尊重优先级 |
| `xdg.desktopEntries` | ❌ 无文件 | 模块可能不生成本地文件 |
| **`home.file` 直接写** | ✅ 生效 | 可靠写入 `~/.local/bin/` + `~/.local/share/applications/` |
