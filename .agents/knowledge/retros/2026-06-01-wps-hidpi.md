# WPS Office HiDPI 修复 — 完整复盘

## 背景

WPS Office 在 2560x1600 高 DPI 笔记本屏幕 + niri Wayland 下 UI 元素偏小喵~

## 最终方案（用户确认）

**只放大演讲备注字体**，不做全局缩放：

```nix
# SlideShowPresenterNotesFontSize 20 → 30 (1.5x)
```

通过 `home.activation` 脚本修改 `Office.conf` 中的 `SlideShowPresenterNotesFontSize`。

## 踩坑记录（重要经验）

### 坑 1: QT_SCALE_FACTOR 会撑爆窗口
- `QT_SCALE_FACTOR=1.75` 让窗口 1.75x 放大，超出 2560x1600 屏幕
- 用户无法操作左侧和下方的窗口
- **教训**: Wayland 下 QT_SCALE_FACTOR 影响窗口几何，高倍率会导致窗口超出屏幕

### 坑 2: 不同缩放倍率的表现
| 倍率 | 结果 |
|------|------|
| 2.0 | 窗口太大，完全无法操作 |
| 1.75 | 窗口太大，只能看到左上角 |
| 1.25 | 还是太大，右边看不到 |
| 1.1 | UI 略大但文档注释变小看不见 |
| **无缩放** | **用户最终选择** |

### 坑 3: common\dpi 只对主 UI 有效
- 设置 `common\dpi=144` 后主页面（开始页）OK
- 但文档内容页面仍然偏小
- **教训**: WPS 内部有多个独立 DPI 系统，主 UI 和文档渲染走不同管道

### 坑 4: ZoomOfFirstView 只影响新建文档
- 设置 `ZoomOfFirstView=200` 后，新建文档 zoom 200%
- 但已打开的文档用自身保存的 zoom 值
- **教训**: 这个设置不是全局覆盖，只影响新文档的默认值

### 坑 5: xdg.desktopEntries 不生成本地文件
- home-manager 的 `xdg.desktopEntries` 没有在 `~/.local/share/applications/` 生成文件
- niri 启动器用的是系统 nix store 中的原始桌面文件
- **教训**: 用 `home.file` 直接写更可靠

### 坑 6: writeShellScriptBin 与同名包冲突
- `pkgs.writeShellScriptBin "wps"` 与 `wpsoffice-cn` 都提供 `bin/wps`
- 在 `home.packages` 中会报 "conflicting subpath" 错误
- **教训**: 不要在 `home.packages` 中同时放原包和同名包装

### 坑 7: symlinkJoin 的 meta.priority 不生效
- 尝试用 `symlinkJoin` + `meta.priority = 1` 覆盖同名文件
- home-manager 的 buildEnv 不尊重这个优先级
- **教训**: meta.priority 在 home-manager 中不可靠

### 坑 8: 用户可能只需要局部放大
- 用户说"UI 太小"，但实际只需要放大演讲备注字体
- 全局缩放反而让注释变小看不见
- **教训**: 先问清楚用户具体要放大什么，不要假设需要全局缩放

## 关键教训

1. **先问再做**: 不要假设用户需要全局缩放，先确认具体需求
2. **增量测试**: 每次改一个设置就让用户测试，不要一次改太多
3. **Wayland 限制**: QT_SCALE_FACTOR 在 Wayland 下会影响窗口几何，高倍率不可行
4. **WPS 多管道**: 主 UI / 文档渲染 / 演讲备注是三个独立系统
5. **回退方案**: 用户说"不行"时要能快速还原所有改动
