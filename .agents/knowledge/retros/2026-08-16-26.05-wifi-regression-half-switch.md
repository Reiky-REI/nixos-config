# 复盘: 26.05 升级断网事故 + switch 半切换残留 (2026-08-16)

## 背景

8/16 凌晨在 `upgrade/nixos-26.05` 分支 `sudo nixos-rebuild switch`, 产出 gen 162 (26.05.20260806.445d861, 内核 6.12.90→6.18.42, WiFi 固件 20260224→20260605)喵~ 重启后 WiFi 连不上, 反复排查实锤三层根因喵~

## 根因 (三层)

### 1. 不是 ASPM 修复回归
`options mt7921e disable_aspm=Y` (commit 05af4aa) 在 gen 161/162 闭包的 modprobe.d 里都存在且生效 (boot -1 内核日志有 `disabling ASPM L1`)喵~

### 2. 断网真因: 内核 6.18.42 + 固件 20260605 组合关联回归
新内核+固件组合与小米 AP 关联不稳喵: 内核层能 associate 但链路掉, NM 反复 `association took too long` + 误判 `asking for new secrets` 喵~ `XIAOMI-周` 2.4G/5G 轮流失败约 8 分钟喵~

### 3. switch 本身失败 (status=4/NOPERMISSION)
dsh-fence 服务抢不到 3080 端口 (当时手动 dsh web 进程占用, EADDRINUSE)喵~ 留下半切换状态喵~

## 修复过程

### A. 止血回滚
- `sudo /nix/var/nix/profiles/system-161-link/bin/switch-to-configuration switch` 激活 gen 161 喵~
- 注意: switch-to-configuration 不更新 profile 指针喵, 需补 `sudo nix-env -p /nix/var/nix/profiles/system --switch-generation 161` 喵~
- 验证三项: current-system→25.11 / system→161-link / loader default→161 全过喵~

### B. 修 dsh web
- 根因: `@nanmicoder/dsh-agent-teams` 上游 commit 没带构建产物 (目录无 `lib/`) 喵~ `.pnpm` store 残缺 (只剩 lock.yaml) 喵~
- 修复: 从 `package.json` 的 `dependencies` 和 `dsh.profile.bundles` 各删掉 `@nanmicoder/dsh-agent-teams`, 移走残缺 node_modules 后 `pnpm install` 喵~
- 发现: 实际 dsh 入口是 `~/node_modules/@deepseek-ai/dsh/lib/bin.js` (全局安装), 不是 profile 的 node_modules/.bin/dsh 喵~ (dsh-fence.nix 的 binPath 也是指这里) 喵~
- 验证: `node --expose-internals ~/node_modules/@deepseek-ai/dsh/lib/bin.js web` → `http://127.0.0.1:3080` 能起喵~

### C. 内核钉版 (用户决策: 升 7.1)
- 交接原方案是钉 `linuxPackages_6_12` 喵, 用户决定改升 7.1 喵~
- 26.05 的 nixpkgs 有 `linuxPackages_7_1` (7.1.6, 同时是 latest) 喵~ 26.05 无 `linuxPackages_lts` 喵~
- 磁盘曾 97% 满导致 nvidia modsrc 拷贝 `No space left on device` 喵~ `nix-collect-garbage` (不删世代) 回收 1.4G + 构建中 auto-GC 释放 5.5G 后 build 成功喵~
- build 产物: gen 163 (26.05 + 7.1.6) 喵~ 只 build 成功, 未重启测试 WiFi 喵~

### D. 切 gen 163 + 后果
- 用户要求继续 (保留 gen 161 即可回滚) 喵, 执行 `rebuild.sh switch` 喵~
- switch 完成后半段: dbus-broker user unit reload 失败 → "user activation for Reiky-REI failed" 喵~ 图形会话 (niri) 未重启但 dbus 层抖动喵~
- 现状: /run/current-system → gen 163 (26.05+7.1.6), 运行内核仍是 6.12.90 (旧, 未重启) 喵~ boot 默认 → gen 163 喵, gen 161/162 都还在 boot 菜单可回滚喵~
- WiFi 目前连通 (旧内核 6.12.90 + 新用户态) 喵~ 7.1.6 的 WiFi 表现需重启后实测喵~

### E. 代理故障 (mihomo/clash) — 影响 opencode API
- 现象: opencode 连不上 deepseek API 喵~
- 根因: clash-verge.service 10:08 死亡 (clean exit), mihomo 不在监听 7897 喵~ 但系统全局代理 `networking.proxy` 硬编码指向 `http://127.0.0.1:7897` 喵~ → opencode 流量进死代理 → 全挂喵~
- 验证: 直连 api.deepseek.com → 401 (可达) 喵, 走代理 → 000 (死) 喵~
- 修复: 用 clash-verge 的运行时配置拉起 `verge-mihomo -d ~/.local/share/io.github.clash-verge-rev.clash-verge-rev -f clash-verge.yaml` 喵~ (GUI 路径已自动托管, 监听 `*:7897`) 喵~
- 顺带: `cache.db` 属主是 root (clash-verge-service 以 root 跑过), 已 chown 喵~

## 遗留

- gen 163 (7.1.6 内核) 未重启验收 WiFi 喵~ 重启后如仍关联不稳, 在 boot 菜单选 gen 161 回滚喵~
- home-manager user activation 半失败 (dbus-broker reload) 喵, 磁盘上的 HM 配置已是新版 (07:34), 重启后用户态自愈喵~
- dsh 的 `@nanmicoder/dsh-agent-teams` 从 profile 里删了 (上游缺构建产物) 喵, 后续上游补产物后可加回喵~

## 经验

1. **switch 失败后必查 `/boot/loader/loader.conf` 默认代** — 半切换会把默认留在新代, 重启即入坑 (已知问题已补)
2. **switch-to-configuration 不更新 profile 指针** — 回滚要额外 `nix-env --switch-generation`
3. **改完包从 `dependencies` 和 `bundles` 两处都要删** — 只删一处 pnpm 还是会拉
4. **代理挂了全系统断网且无声** — 全局 proxy env 硬编码, mihomo 一死 opencode/nix/git 全挂, 排查先查 `ss -tlnp | grep 7897`
5. **磁盘 97% 时 nvidia 模块编译会静默失败** — "No space left on device" 出现在 modsrc 拷贝, 看似 nvidia 问题实则磁盘
6. **26.05 无 `linuxPackages_lts`** — 用 `linuxPackages_6_12` 或 `linuxPackages_7_1`
7. **gen 保留策略** — `nix-collect-garbage` 不带 `-d` 只清不可达, 世代安全
