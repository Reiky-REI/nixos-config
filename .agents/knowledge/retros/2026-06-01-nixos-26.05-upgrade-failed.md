# 复盘: NixOS 25.11 → 26.05 升级失败分析

## 尝试概述

2026-06-01，nixos-26.05 正式版发布。尝试将系统从 25.11 全量升级到 26.05，
包含：通道升级、内核升至 `linuxPackages_latest`、蓝牙补丁清理。
耗时约 8 小时，多次 build 失败后回退。

## 失败原因链

### 根本原因：磁盘空间不足（100G 瓶颈）

/build 目录在根分区上，无独立挂载。每次源码编译 + pnpm/yarn 下载依赖
都吃临时空间。100G 磁盘在同时容纳新旧两套 nixpkgs 时捉襟见肘。

### 连锁失败的包（按出现顺序）

| 包 | 原因 | 类型 |
|----|------|------|
| `electron-39.8.10` | 被标记为 insecure | 元数据 |
| `logseq-0.10.15` | 构建失败（yarn 依赖下载+编译，疑似 OOM） | yarn + ClojureScript |
| `whiskers-2.9.0` | No space left on device | Rust 编译 |
| `xwayland-24.1.11` | No space left on device (并发编译) | C (meson) 编译 |
| `nvidia-x11-595.71.05` | .run 文件从镜像下载失败 | 网络/镜像 |
| `facetimehd-calibration` | curl: Could not resolve host (Apple) | 网络/DNS |
| `splayer-3.0.0` | ENOSPC pnpm install (1139 npm 包) | Rust + pnpm |

### 阻塞模式

每个失败都是"1 dependency failed"连锁反应 → 整个系统 toplevel 构建失败。
由于 nix 的全量评估性质，任何一个包的失败都会阻塞整个系统构建。

## 升级条件清单（下次满足后方可尝试）

### 磁盘空间

| 条件 | 要求 | 说明 |
|------|------|------|
| 当前空闲 | **≥ 40G** | 25G 实测不够，40G 留余量 |
| /build 临时空间 | 至少 10G | pnpm/yarn 和编译中间文件 |
| 目标 | `/nix/store` 所在分区 ≥ 50G 空闲 | 新旧两套 nixpkgs 共存 |

### 内存

| 条件 | 要求 |
|------|------|
| 物理内存 | ≥ 16G（当前 14G 在 Rust 编译时触发 swap） |
| swap | ≥ 8G（当前 16G swap 够用） |

### 编译时间预算（max-jobs=auto）

| 阶段 | 时间 | 说明 |
|------|------|------|
| 下载（镜像有缓存） | ~10-20 min | 大部分包从 TUNA/USTC 走 |
| 下载（cache.nixos.org） | ~30-60 min | 镜像没有的包回退到官方源 |
| 编译（Rust） | ~30 min | whiskers + splayer + neovide |
| 编译（C/C++） | ~60-90 min | fcitx5 生态 + quickshell + xwayland + glibc-locales |
| pnpm/yarn 构建 | ~15 min | splayer, logseq |
| 系统链接 | ~5 min | 最终 toplevel 构建 |
| **总计** | **~2.5 - 4 小时** | 取决于镜像缓存命中率和网络速度 |

### 升级策略

```
第 1 步: 只改 flake.nix 三个 url（nixpkgs/catppuccin/home-manager）
        不碰内核、不改包、不动 firmware
        build → switch → 验证 → GC 清掉旧 25.11 包

第 2 步: 内核升级 linuxPackages → linuxPackages_latest
        build → reboot → 验证 → GC

第 3 步: 逐个添加包（splayer, neovide 等需要编译的放在最后）
        每个包独立 build 验证

第 4 步: NVIDIA PRIME 恢复
        独立处理 nvidia-x11 下载
```

### 前置检查清单

```bash
# 1. 检查磁盘
df -h /          # 需 ≥ 40G 空闲

# 2. 检查镜像缓存
nix store ping --store https://mirrors.tuna.tsinghua.edu.cn/nix-channels/store

# 3. 清理旧 generation
sudo nix-collect-garbage --delete-older-than 7d
sudo nix store optimise

# 4. 评估编译源
# 查看哪些包需要本地编译（不在缓存中）：
nix store path-info --all --json \
  $(nix eval .#nixosConfigurations.NixMEOW.config.system.build.toplevel.drvPath) \
  2>&1 | jq '.[] | select(.valid == false) | .path'
```

## 教训总结

1. **"可源自话构建" ≠ "必须本地编译"** — NixOS 的优势是二进制缓存。
   新版本发布初期镜像缓存不全时，升级成本会急剧上升。
2. **磁盘是硬瓶颈** — 100G 不够，尤其同时编译 Rust/C++/npm 时。
3. **逐级升级优于全量升级** — 通道升完→GC→内核→GC→包，避免连锁失败。
4. **pnpm/yarn 类包是坑** — 它们会在 build 阶段二次下载 npm 依赖，
   无法从 nix 二进制缓存受益，需要额外临时空间。
5. **NVIDIA PRIME 在新内核上需要单独处理** — .run 文件 423MB 下载可能失败，
   建议预下载好再 build。
